## 保留的决策

- GameState 全部字段私有，外部只通过动作、tick 和 reset 修改状态；边界场景在核心内部测试构造。
  编译失败文档测试保护状态字段和棋盘写入边界。
- 保持单 package，通过默认 desktop feature 隔离桌面依赖；核心与 Runtime 可无窗口测试。
- 棋盘占用只保留 Cell.kind；HUD 按实际值变化刷新；音频由 callback 独占有界 voice 缓冲区。
- state_hash 是实现内的 opaque identity，不是包含全部 RNG/config 的恢复检查点。

## 验证证据与范围

以下应用和依赖结果来自本次审计期间的验收，不代表后续每次修改都重新执行了这些检查。

- 桌面与无默认 feature 的测试、Clippy、文档测试及格式检查通过。
- 本地应用在源码目录外启动，图标与资源完整，10 个 WAV 与源码资源逐一校验一致。
- 上游 `adapter_verify.py all` 的 ready、claim、restart、determinism 通过。
  最小化后独立 TCP 客户端测得约 1.005 秒推进 63 个逻辑步，playable 为 true。
- 可见窗口的键盘操作、缩放、全屏往返和设置控件经过检查；设置打开时远程 restart 后覆盖层关闭。
  自动化截图有保留旧帧的现象，不能据此宣称所有遮挡/恢复场景都完成人工视觉验收。
- 用户不要求实体手柄操作和扬声器试听；软件输入状态、混音输出和资源打包已有验证。
- 切帧隔离基准中，65,536 个短帧按每轮 64 帧处理，16 次采样总耗时中位数约 2.3 ms；
  原实现约 130 ms。两次机器负载不同，仅作算法改进证据，不是应用延迟保证。
- 修正 chacha20 撤回版本后，在线 `cargo audit --deny yanked` 未检出已知漏洞或撤回依赖。
  当时 RustSec 数据库 commit 为 `5a0ebedfe8bdd2e295b171f4162f8c977bcad9a5`（2026-09-02）；
  上游维护状态与未来 Rust 兼容性提示仍保留。持续检查方式见依赖维护文档。

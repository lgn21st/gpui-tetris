# 架构审计收尾记录

日期：2026-09-04。范围：核心状态封装、依赖检查与本地应用验收。

## 核心封装

- GameState 的全部字段改为私有；UI、Runtime 和 Adapter 使用只读访问器。
  棋盘和预览队列仅返回共享引用，活动块返回副本。
- spawn/scoring 等内部修改入口不再对外公开。协议事件只允许借用，不再
  暴露可消费事件的接口；声音通过 drain 消费。
- 需要直接构造计分、锁定延迟或异常边界状态的规则测试迁入核心模块，
  不增加生产 fixture feature、任意 setter 或可变状态访问器。
- TCP 消行测试使用 seed 1 的合法动作序列构造一行消除；暂停准备也走动作。
- 保留 135 项桌面测试、114 项无界面测试，并新增 2 项 compile-fail 文档测试
  防止重新开放状态字段和棋盘写入。两种配置的 Clippy 与格式检查通过。

这是 Rust 公共 API 的收紧，旧的直接字段访问、spawn/scoring 和 take-events
调用需要迁移；线上协议没有变化。

## 依赖检查

完整在线审计发现 chacha20 的锁定版本已撤回，将它更新至同一兼容范围内的
未撤回版本；没有批量更新其他依赖。重新运行 `cargo audit --deny yanked`
得到 0 个已知漏洞、0 个撤回依赖。

本次获取的 RustSec 数据库 commit：
`5a0ebedfe8bdd2e295b171f4162f8c977bcad9a5`，数据库更新时间 2026-09-02。
仍保留 bincode、instant、paste、rustls-pemfile、rustybuzz、ttf-parser 的
6 项上游 unmaintained 警告，以及 block 的未来 Rust 兼容性提示；这些并不
等于已知漏洞，也不以忽略规则隐藏。后续跟随 Kit 上游依赖栈维护。

增加 Dependency security 工作流：每周、锁文件变化及手动触发时在线审计，
对已知漏洞和 yanked 明确失败。审计结果只代表本次数据库与锁文件时点。

## 实际窗口和设备的证据范围

- 普通可见窗口连续落块，分数 36→60；设置覆盖层和控件显示正常。
- 已检查全屏往返；最小化期间 upstream verifier 的 ready、claim、restart、
  determinism 通过。恢复过程中从系统重新打开应用能取得后续游戏画面。
- 自动化抓图仍可能返回先前的窗口帧。对照实验中键盘 restart 已使 Adapter
  的 episode_id 8→9、score 36→0，但同轮截图尚未反映新状态。这证明核心
  接受并执行了输入，不能单凭该截图判定渲染故障，也不能据此宣称完整视觉验收。
  Dock 的自动化恢复调用超时，已换用 Finder；不为自动化工具行为加入游戏补丁。
- 用户明确不要求实体手柄操作或扬声器试听，此项也不作为收尾待办。
  已覆盖软件输入状态、混音和资源打包；没有宣称真实设备测试通过。
